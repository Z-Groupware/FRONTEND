# DESIGN.md — 화면 만들 때 밟는 순서 · 겪은 함정

> 📌 **값(토큰·폭 표)은 [`CONVENTIONS.md`](CONVENTIONS.md) §8·§9가 정본이다.** 여기는 그 값을
> **언제 어떻게 고르는지**와 **틀렸을 때 어떤 일이 나는지**를 적는다.
> **화면별 요구사항은 [`WORKFLOW.md`](WORKFLOW.md)** 를 본다 — 이 문서는 무엇을 만들지가 아니라
> 어떻게 만드는지다.
>
> ⚠️ 아래 사례는 전부 **실제로 났던 일**이다. 만들 때 알았으면 안 났을 것들만 남겼다.

---

## 0. 만들기 전 5분

새 화면을 열기 전에 이 여섯 개만 정하면 대부분의 재작업이 없어진다.

| #   | 정할 것                                                 | 어디서  |
| --- | ------------------------------------------------------- | ------- |
| 1   | 이 화면은 **목록인가 · 폼인가 · 읽는 글인가**           | §1 폭   |
| 2   | 카드가 바탕에서 **뜨는가**                              | §2 표면 |
| 3   | 표라면 **각 열이 무엇을 축으로 서는가**                 | §3 표   |
| 4   | 색을 쓸 자리가 **뜻이 있는 자리인가**                   | §4 색   |
| 5   | 화면이 말하는 값이 **BE가 준 사실인가**                 | §6 값   |
| 6   | `loading` · `error` · `empty` 세 장을 **같이 만드는가** | §5 상태 |

> 🧱 **새 화면은 §11(구독·저장소 화면)에서 골격을 베껴 시작한다.** 카드 껍데기·머리·글자
> 크기·여백·표가 다 거기 있다 — 처음부터 다시 정하면 팀원끼리 생김새가 갈린다.

## 1. 폭 — 새 숫자를 만들지 않는다

```
목록·표         → max-w-[1440px]     (대시보드 · 저장소 · 공지 목록 · 캘린더)
상세 2컬럼      → max-w-[1440px]
폼 + 좌 네비    → max-w-[960px]      (네비 180px 포함)
폼 한 장        → max-w-[720px]      (마이페이지 · 공지 작성/수정)
읽는 글         → max-w-[720px]      (공지 상세 카드)
로그인·확인     → max-w-[560px]
```

**⚠️ 겪은 일**

- **1080·1120·1144가 흩어져** 사이드바로 옮겨 다닐 때 본문 폭이 눈에 띄게 흔들렸다.
  대시보드 3종과 구독이 1080이라 캘린더·저장소보다 좁았다.
- **저장소는 `loading` 1080 · 본문 1440**이라 로딩이 끝나는 순간 폭이 확 넓어졌다.
  → **스켈레톤은 완성된 화면과 같은 폭·같은 개수**여야 한다. 카드 3개를 그려 놓고
  실제로 2개면 데이터가 채워질 때 본문이 위로 튄다.
- 폼을 960으로 늘리려다 말았다 — **좌 네비가 없으면 입력칸만 넓어져** 읽고 쓰기가 나빠진다.
  항목이 늘어 네비가 생기는 날 960으로 올린다. **1440으로 올리지 않는다**(그건 목록용이다).

**고정하지 않는다** — `w-[1440px]`이 아니라 `mx-auto max-w-[1440px] px-8`.
1440은 "이 크기로 고정"이 아니라 **"여기까지만 넓어진다"** 는 뜻이다.

## 2. 표면 — 카드가 안 뜰 때

라이트에서 `--background`와 `--card`는 **둘 다 흰색**이다. 그래서 카드를 나누는 건
보더선 하나뿐이고, 그것만으로는 화면이 통째로 하얗게 뜬다.

**답: 색이 아니라 깊이다.** 카드에 얕은 그림자를 건다(`.app-shell .bg-card`).

**⚠️ 색으로 띄우려는 시도는 세 번 다 실패했다**

| 시도                          | 결과                                              |
| ----------------------------- | ------------------------------------------------- |
| 본문만 `#FAFAF9`(중성)로 내림 | 옆의 흰 사이드바와 비교돼 **시멘트색**으로 읽혔다 |
| 본문만 `#FAF8F4`(크림)로 내림 | 껍데기와 본문이 갈려 **따로 노는** 느낌           |
| 셸·본문 전부 크림             | 화면 전체가 **누런 종이**                         |

**왜 다크는 되고 라이트는 안 되나** — 어두운 색은 색조가 안 읽힌다. 다크의 `#1A1715`도
갈색기지만 그냥 검정으로 보인다. 밝은 색은 색조가 그대로 읽혀서 화면 전체를 덮으면 누레진다.

- **다크에는 그림자를 안 건다.** 어두운 바탕에서 거의 안 보이고, 거기선 카드가 이미 밝다.
- **점 그리드는 로그인 뒤에 안 깐다.** `.bg-dot-grid`는 랜딩·온보딩·결제 전용이다.

## 3. 표 — 열마다 축이 따로 선다

가장 많이 어긋나는 곳이다. **묶음을 가운데 두면 안 된다** — 안에 든 글자 길이가 다르면
그 줄만 밀린다.

**⚠️ 겪은 일 셋 — 원인이 전부 같다**

| 어긋난 것                         | 원인                                         | 고친 법                         |
| --------------------------------- | -------------------------------------------- | ------------------------------- |
| 상태 콩이 줄마다 좌우로 밀림      | `진행중`(3자)·`완료`(2자)를 묶어 가운데 정렬 | 라벨 상자 폭 고정               |
| 음성 막대가 한 줄만 왼쪽으로 밀림 | `10.9GB`(4자리)가 `9.1GB`보다 넓음           | 숫자 상자 폭 고정 + 오른쪽 정렬 |
| 머리글과 아이콘이 안 맞음         | 머리 여백(`px-7`)과 셀 여백(`pr-5`)이 다름   | 머리 글자를 실측만큼 민다       |

```tsx
❌ <span className="flex justify-center gap-2">{dot}{label}</span>
✅ <span className="mx-auto w-fit flex gap-2">{dot}<span className="w-[42px] text-center">{label}</span></span>
//   묶음은 가운데, 라벨 상자는 고정폭 → 점은 점끼리, 글자는 가운데끼리 선다
```

**열 폭은 비율(%)로 준다.** px로 고정하면 남는 폭을 첫 열이 통째로 먹어서, 넓은 화면에서
이름 왼쪽만 텅 비고 나머지 값이 오른쪽에 구겨진다.

**그 밖에**

- **아이콘만 있는 열에도 머리글을 준다.** `sr-only`로만 두면 표가 한 칸 덜 끝난 것처럼 보이고
  아이콘이 무엇을 하는지 머리에서 안 읽힌다.
- **버튼을 줄마다 있다 없다 하지 않는다.** 자리는 늘 두고 **못 하는 줄은 잠그고 `title`로 이유**를
  말한다 — 열이 비면 기능이 없는 건지 이 줄만 안 되는 건지 알 수 없다.
- **영문 슬러그를 한글 이름 옆에 붙이지 않는다**(`제품 v2.0  #product-v2`). 같은 것을 두 번 말하고,
  눈이 먼저 닿는 열이 영어로 시작한다. 구분이 필요하면 **줄 왼쪽 색 띠**가 맡는다.
- 세로 띠를 쓸 때는 카드에 `overflow-hidden` — 없으면 마지막 줄 띠가 둥근 모서리 밖으로 나간다.

## 4. 색 — 뜻이 있는 자리에만

**색으로 알리는 건 에러(빨강)뿐이다.** 나머지는 명도·아이콘·문구로 구분한다.

색을 써도 되는 자리는 **그 색이 무엇인지 답할 수 있을 때**다.

| 자리             | 뜻                                              |
| ---------------- | ----------------------------------------------- |
| 상태점           | 할일 회색 · 진행중 초록 · 완료 보라 · 지연 빨강 |
| 프로젝트 띠·막대 | 어느 프로젝트인지 (`lib/palette`)               |
| 프로필 아바타    | 그 사람 (`useProfileAvatar` — 키는 **id 하나**) |
| 초과             | 빨강                                            |

**⚠️ 겪은 일**

- 팔레트 원색이 **700단계**라 명도 0.08~0.16이었다. 다섯 줄이 전부 시커멓게 보여
  "색이 몇 개 없다"고 읽혔다 → **600단계**로 올렸다.
  단 `yellow`·`lime`은 600에서 트랙 대비가 3:1에 못 미쳐 700을 유지한다.
- 아바타 색 키가 부르는 쪽마다 달라(`name+id` / `name+department`) **같은 사람이 화면마다
  다른 색**이었다. 이름·부서는 바뀌는 값이라 키에 넣으면 그때 색이 통째로 바뀐다.
- **비문자 그래픽은 3:1, 글자는 4.5:1**이다(WCAG). 막대·아이콘을 옅게 깔 때 확인한다.

## 5. 상태 — 세 장을 같이 만든다

`loading` · `error` · `empty`는 **나중에 붙이는 게 아니라 같이 만드는 것**이다.

- **스켈레톤은 완성 화면과 같은 자리**를 잡는다(§1 참고).
- **`error.tsx`가 셸 안이면 `isInsideShell`을 켠다.** 안 켜면 상단바 56px + 100dvh가 되어
  아래가 잘리고 스크롤도 안 된다. 창이 낮으면 [다시 시도] 버튼이 잘린 영역에 들어가
  **오류에서 빠져나갈 길이 사라진다.**
- 셸 안에서는 `h1`을 쓰지 않는다 — 위에 `PageHeader`의 `h1`이 남아 한 페이지에 제목이 둘이 된다.
- **화면이 아직 없으면 사이드바가 자동으로 안다**(`routes.ts`). 손으로 `isReady`를 켜지 않는다.

**empty는 "무엇이 없는지 + 다음에 뭘 하면 되는지"를 같이 적는다.**

## 6. 값 — 지어내지 않는다

**화면은 BE가 준 사실만 말한다.**

**⚠️ 겪은 일 — 프론트가 예측을 만들고 있었다**

`주기 종료 시 1,441,500 예상`은 BE 응답에 없는 값이었다. `쓴 양 ÷ 지난 일수 × 주기 일수`로
프론트가 만든 것인데, 31일 주기에서 **4일치로 한 달을 곱하고** 있었고 회의가 주중에 몰리는데
"매일 똑같이 쓴다"를 전제한 식이었다. `50GB 예상`은 49.8GB의 반올림이라 포함량과 같은 숫자로
보여 "딱 맞겠네"로 읽혔다.

같은 파일 주석이 _"금액은 서버와 다를 수 있어 안 만든다"_ 면서 **양은 만들고** 있었다.

> **BE 스펙에 없으면 화면에 없다.** 필요하면 BE에 요청하고 그 값을 받아 쓴다.

**정책도 마찬가지다.** `자막·요약 삭제 불가`는 팀이 정한 적 없는데 화면이 단언하고 있었다 —
정해지지 않은 것은 **화면이 말하지 않는다**.

## 7. 그래프 — 무엇을 견주는지로 고른다

| 묻는 것                 | 형태                                  |
| ----------------------- | ------------------------------------- |
| 얼마나 찼나 (하나)      | 링 · 막대 둘 다 됨                    |
| **두 조각의 크기 비교** | **가로 막대** — 같은 축에 이어 놓는다 |
| 시간에 따른 변화        | 선                                    |

**⚠️ 겪은 일** — 저장소 요약을 링으로 그렸는데, 이 화면이 판단할 것은 "음성이 자막·요약보다
얼마나 큰가(= 지워서 얼마나 버나)"였다. **원은 두 조각을 나란히 견주기 어렵다.**

- 링은 **한 바퀴를 넘어 못 그린다.** 초과하면 100%에서 잘려 1GB를 넘겼는지 12GB를 넘겼는지
  그림으로 구분이 안 됐다. 막대는 넘긴 만큼 그리고 **포함량 자리에 한도선**을 그으면 된다.
- `strokeLinecap="round"`는 선 굵기의 절반만큼 **양끝으로 삐져나온다.** 69.8%인 조각이
  73%처럼 보이고 뒤 조각을 덮는다 — 눈금이 안 맞아 보이던 원인이다.

## 8. 글 — 짧게, 우리 말투로

- **~합니다체**다(2026-08-04 변경). `~해요체`가 남아 있으면 그건 그 전 것이다.
  돈·권한·기록이 걸린 화면이라 친근한 말투가 오히려 가볍게 읽힌다.
- **버튼은 한 낱말**이다 — `삭제`·`해지`·`발송`·`추가`·`등록`.
  `해지할게요`(해요체)도 `그대로 둡니다`(장황)도 아니다. 이유·결과는 설명이 맡는다.
  `cancelLabel`은 웬만하면 안 넘긴다 — 기본값 `취소`가 있는데 창마다 다른 말을 쓰면
  같은 자리가 매번 다르게 읽힌다.
- **날짜는 `formatDate`를 거친다.** `2026-09-01`은 개발자용 표기다 → `9월 1일(화)`.
- **긴 설명은 뜻 단위로 끊는다.** 한 줄로 두면 창 폭에서 아무 데나 접혀
  `워크스페이스에` / `접근할 수 없습니다`처럼 갈린다.
- **조사를 박지 않는다.** `${label}은`으로 고정하면 `프로젝트은`이 된다 —
  `lib/korean.ts`의 `topicParticle`이 받침을 보고 고른다.
- **라벨을 하드코딩하지 않는다.** 값은 `constants/`의 `*_LABEL` 맵에서 꺼낸다.

## 9. 빈 자리 — 넓은 카드에 한쪽만 쓰지 않는다

**⚠️ 겪은 일** — 요약 카드가 1440인데 링과 숫자가 왼쪽 절반만 쓰고 오른쪽이 통째로 비어
"보여 줄 게 없는 화면"처럼 읽혔다. 그 자리에 **이 화면에 온 이유의 답**(삭제 가능 용량)을
세웠는데, 그 값은 이미 계산하고 있었고 어디에도 안 보였을 뿐이다.

- **`flex-1`을 쓰면 늘어난 칸 안에서 내용이 왼쪽에 몰려** 그 칸의 오른쪽만 빈다.
  칸을 똑같이 나누려면 `grid-cols-3`으로 두고 칸마다 가운데 정렬한다.
- 칸은 **세로선 하나**로만 가른다. 오른쪽에 카드를 또 얹으면 카드 안에 카드가 생긴다.
- **머리와 본문 사이에 선을 긋지 않는다.** 제목·안내는 한 덩어리인데 선을 그으면 층이
  하나 더 생겨 카드가 늘어나 보인다 — 카드 안의 선은 **표가 시작하는 자리** 한 곳뿐이다.

## 10. 마지막 점검

화면을 올리기 전에 이것만 본다.

- [ ] **다크모드**로 한 번 본다 — `dark:`를 직접 썼으면 토큰을 안 쓴 것이다
- [ ] **좁은 창**으로 줄여 본다 — 표가 가로 스크롤로 넘어가는지
- [ ] `loading` → 실제 화면으로 넘어갈 때 **폭·개수가 안 튀는지**
- [ ] 표의 각 열이 **세로로 한 줄에 서는지**(§3)
- [ ] 화면에 적힌 숫자가 **BE가 준 값인지**(§6)
- [ ] 버튼 문구가 **한 낱말인지**, 날짜가 **우리 표기인지**(§8)
- [ ] `npx jest` · `npm run build`

## 11. 만들 때 그대로 베끼는 것 — 구독 · 저장소 화면

> 이 두 화면(`/manage/billing` · `/manage/storage`)이 **양식의 기준**이다. 새 화면을 만들 때
> 여기서 골격을 가져다 쓰면 팀원끼리 화면 생김새가 갈리지 않는다.
> 실제 파일: `features/billing/components/*` · `features/storage/components/*`

### 11-1. 화면 골격

```tsx
// page.tsx — 조회는 Server Component가 한다
export default async function Page() {
  const [data, config, viewer] = await Promise.all([...]);
  return <View data={data} config={config} canManage={canX(viewer)} />;
}

// layout.tsx — 상단바는 여기서 그린다(본문이 아니라)
<PageHeader title="저장소 관리" icon={HardDrive} />
```

```tsx
// View — 스크롤은 여기서, 폭도 여기서
<div className="flex-1 overflow-y-auto px-8 py-7">
  <div className="mx-auto w-full max-w-[1440px]">
    <div className="flex flex-col gap-7">
      <SummaryCard /> {/* 요약 한 장 */}
      <DetailTable /> {/* 내역 한 장 */}
    </div>
  </div>
</div>
```

**⚠️ 카드를 세 장 이상 쌓지 않는다.** 두 화면 다 **요약 → 내역** 두 장이다.
카드가 늘면 무엇을 먼저 봐야 하는지 흐려진다 — 늘리기 전에 위 카드에 넣을 수 있는지 본다.

### 11-2. 카드 껍데기

```tsx
<section className="border-border bg-card rounded-2xl border">
  {" "}
  {/* 표가 들어가면 + overflow-hidden */}
  <div className="flex items-baseline justify-between gap-3 px-7 pt-6 pb-3">
    <h2 className="flex items-center gap-2 text-[17px] leading-7 font-semibold tracking-[-0.3px]">
      <span className="bg-foreground size-2 rounded-full" aria-hidden /> {/* 머리 표식 */}
      프로젝트별 사용량
    </h2>
    <p className="text-muted-foreground text-[12px] leading-4 tabular-nums">전체 5개</p>
  </div>
  {/* 본문 */}
</section>
```

- **머리 표식(`size-2` 먹색 점)** 은 모든 카드 제목에 붙는다 — 화면이 달라도 같은 서비스로 읽힌다.
- **오른쪽 끝에 보조 정보 한 줄**(전체 건수 · 주기 범위). 버튼을 두지 않는다.
- 제목과 안내 문구 **사이에 선을 긋지 않는다**(§9).

### 11-3. 요약 카드 — 세 칸 균등

```tsx
<div className="grid gap-6 pt-6 lg:grid-cols-3 lg:items-center lg:gap-0">
  <div className="flex flex-col items-center gap-3 lg:px-4">…</div>
  <div className="border-border lg:border-l lg:px-6 …">…</div>
  <div className="border-border lg:border-l lg:px-6 …">…</div>
</div>
```

- **칸은 세로선으로만** 가른다. 카드 안에 카드를 얹지 않는다.
- 칸마다 구조가 같다 — `작은 라벨 → 큰 값 → 보조 문구`.
- 좁아지면 세로로 쌓는다(`grid` 기본 1열, 세로선은 `lg:`에서만).

**라벨·값 한 쌍**은 이 모양이다(`Metric`):

```tsx
<dt className="text-muted-foreground text-[12px] leading-4">월 기본료</dt>
<dd className="pt-1.5 text-[20px] leading-7 font-semibold tracking-[-0.4px] tabular-nums">₩150,000</dd>
<p className="text-muted-foreground/70 pt-0.5 text-[11px] leading-4">보조 설명</p>
```

### 11-4. 글자 크기 — 다섯 개만 쓴다

| 쓰임         | 크기                                                          |
| ------------ | ------------------------------------------------------------- |
| 카드 제목    | `text-[17px] leading-7 font-semibold tracking-[-0.3px]`       |
| 큰 숫자      | `text-[30~32px] leading-9/10 font-semibold tracking-[-0.8px]` |
| 본문         | `text-[13px] leading-5`                                       |
| 라벨·보조    | `text-[12px] leading-4`                                       |
| 더 작은 힌트 | `text-[11px] leading-4`                                       |

- **숫자에는 `tabular-nums`** 를 붙인다 — 안 붙이면 자릿수가 바뀔 때 좌우로 흔들린다.
- 새 크기를 만들지 않는다. 위 다섯으로 안 되면 그 자리 구조가 잘못된 것이다.

### 11-5. 여백

```
카드 안쪽     px-7 (28px)      ·  세로는 pt-6 pb-3(머리) / p-7(단일)
카드 사이     gap-7 (28px)
표 셀         px-4 py-3.5      ·  첫 열만 px-6
본문 바깥     px-8 py-7
```

### 11-6. 표

§3이 정렬을 다루고, 여기는 **골격**이다.

```tsx
<div className="border-border overflow-x-auto border-t">
  {" "}
  {/* 표 시작 = 카드 안 유일한 선 */}
  <table className="w-full min-w-[760px] table-fixed text-[13px]">
    <colgroup>{/* 폭은 % 로 */}</colgroup>
    <thead>
      <tr className="text-muted-foreground bg-secondary/50 border-border border-b text-[12px] leading-4">
        <th className="px-6 py-3 text-left font-normal">프로젝트</th> {/* 이름만 왼쪽 */}
        <th className="px-4 py-3 text-center font-normal">상태</th> {/* 나머지 가운데 */}
      </tr>
    </thead>
    <tbody>{/* 줄: group border-t hover:bg-foreground/[0.04] */}</tbody>
  </table>
</div>
```

- **머리에 섹션 띠**(`bg-secondary/50`) — 보더 한 줄만으로는 머리와 본문이 같은 면으로 읽힌다.
- **줄 강조는 `hover:bg-foreground/[0.04]`** 다. `--secondary`는 흰 카드와 2%밖에 차이가 없어
  손이 어느 줄에 있는지 안 보인다.
- **이름 열만 왼쪽, 나머지는 가운데.** 이름은 길이가 제각각이라 가운데로 모으면 왼쪽 끝이
  들쭉날쭉해져 세로로 훑을 수가 없다.

### 11-7. 이 두 화면이 지키는 것

|                             |                                |
| --------------------------- | ------------------------------ |
| 상단바에 버튼을 두지 않는다 | 액션은 카드 안에 둔다          |
| 카드는 두 장                | 요약 → 내역                    |
| 색은 뜻이 있는 자리만       | 상태점 · 프로젝트 띠 · 초과    |
| 파괴적 작업은 창으로 확인   | 무엇을 잃는지 먼저 적는다      |
| 넘겨도 막지 않는다          | 얼마가 더 나가는지 적고 보낸다 |
