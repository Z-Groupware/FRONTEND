| 항목       | 결정                                                             |

| 언어       | TypeScript **strict** + `noUncheckedIndexedAccess`               |

### 분업 — 화면 축 3분할

> 기능 축(캡처/실시간/뷰)으로 나누면 **캡처 화면 하나를 둘이 만지게 되어** 충돌한다. 화면 축으로 나눈다.

| 담당           | 범위                                                                                  | 화면 수  |
| -------------- | ------------------------------------------------------------------------------------- | -------- |
| **① 워크벤치** | `/app/meeting/*`(캡처·AI검토 포함) · `/app/rooms` · 캘린더                            | ~12      |
| **② 업무**     | `/app/board` · 액션 · 프로젝트 · 인수인계                                             | ~14      |
| **③ 조직·셸**  | `(role)` 대시보드 4종 · 사원/회의실 관리 · 구독 · **공유 셸·디자인 시스템 단독 소유** | ~15 + 셸 |

- **캡처(녹음) + STT(자막)는 한 화면** → 반드시 ①에게. 나누지 않는다.
- **공유 셸**(`app/layout.tsx` · 사이드바 · `globals.css` · `middleware.ts` · providers) = **③ 단독 소유 + 별도 PR로만.**
- Public · 온보딩은 초반에 나눠 빠르게 끝내거나 ③이 흡수.
- ⏳ **누가 ①②③을 맡을지는 미정** (아래 미결정 참조)

### 라우트 그룹

```
app/
├─ (public)/      /  /login  /register  /pricing  /invite/[token]
├─ (onboarding)/  /onboarding/*
├─ (role)/        owner | manage | team | my    ← 셸 공유, 네비만 역할별
├─ (app)/         /app/*                        ← 공용 워크벤치(권한 차등)
└─ (system)/      /system/*                     ← 확장
```

- `(role)` 4개는 **레이아웃 1개 + 역할별 네비 구성**. 4벌 복붙 금지.
- `/owner`·`/manage`는 사원관리 권한이 거의 같다 → **공용 컴포넌트 + 권한 prop.**
- `/app/*`은 라우트를 쪼개지 말고 **컴포넌트 레벨 가드.**

### 도입할 것

| #                                                | 항목 | 이유                                                                                                             |
| ------------------------------------------------ | ---- | ---------------------------------------------------------------------------------------------------------------- |
| **zod 계약 SSOT + 매퍼 `safeParse`**             | ✅   | ERD·API가 없어 목으로 먼저 간다. shape가 어긋나면 **가짜 데이터가 화면에 뜬 채 모른다** — zod가 연동 전에 터뜨림 |
| **shadcn/ui + cva + cn**                         | ✅   | 폼·테이블·모달·캘린더가 많음. raw div면 3명 스타일이 갈리고 a11y가 샘                                            |
| **CI 필수 체크 4종**                             | ✅   | PR마다 `typecheck·lint·test·build` 전부 통과해야 머지. develop 보호 + 리뷰 1명 + 직접 push 금지                  |
| **공용 목 팩토리(faker ko)**                     | ✅   | 3명이 각자 만들면 shape가 갈림. **1명이 소유**                                                                   |
| **계약 선(先)머지**                              | ✅   | 병렬 착수 전에 `schemas.ts`/`types.ts`만 담은 작은 PR을 먼저 머지 → 3인이 같은 shape 공유                        |
| **husky + lint-staged + Prettier + import 정렬** | ✅   | 커밋 자체가 정리된 상태로만 생성                                                                                 |

### 도입 안 할 것

| 항목                                       | 왜 안 하나                           | 대신                                                                                                                                                         |
| ------------------------------------------ | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **plop 스캐폴딩 + 골든 레퍼런스**          | 초기 셋업 비용 대비 3인·1개월엔 과함 | ⚠️ **구조 일관성은 `CONVENTIONS.md §2`와 리뷰로만 지킨다.** 첫 도메인을 만들 때 폴더 4파일(`schemas·types·server·actions`) 형태를 지키는지 리뷰에서 꼭 볼 것 |
| **서버상태 라이브러리(TanStack Query 등)** | Server-First라 조회는 서버가 함      | 클라 상태는 `useState` + Server Action. 정말 부족하면 그때 재논의                                                                                            |
| **commitlint 하드 블록**                   | 마찰만 큼                            | 커밋 규칙(`type: 제목`)은 **유지**하되 훅으로 막지 않고 **PR 리뷰에서** 본다                                                                                 |
| **`/preview` 컴포넌트 카탈로그 확장**      | 화면 만들기가 우선                   | `/preview` 라우트 자체는 화면 목록에 있으니 그대로 두고, 상태 카탈로그는 안 만듦                                                                             |
